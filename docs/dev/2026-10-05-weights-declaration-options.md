# `weights=` 该不该要求声明权重类型

2026-10-05。供决策用，尚未实施任何方案。

## 问题

Stata 用四个关键字区分权重：`[aw=]`、`[pw=]`、`[fw=]`、`[iw=]`。关键字决定方差怎么算。`[pw=]` 会自动换成稳健方差，`[aw=]` 和 `[fw=]` 用基于模型的方差。

StatsPAI 只有一个 `weights=`。用户只传这一个参数时，回归类入口把它当作分析权重或频数权重，报告基于模型的方差。如果用户手里其实是抽样权重或逆概率权重，这个区间会短很多。

## 现状的事实

**涉及范围。** 95 个注册函数接受 `weights=`。其中 67 个的 schema 描述没有说明权重被当作哪一种。

**默认方差。** 在一个权重分散的例子上实测了 14 个回归类入口（对数正态权重，σ = 1.5，n = 600）。

| 入口 | 只传 `weights=` 时的标准误 | 稳健标准误 | 默认是稳健的吗 |
| --- | ---: | ---: | --- |
| `sp.regress` | 0.039 | 0.111 | 否 |
| `sp.logit` | 0.058 | 0.213 | 否 |
| `sp.probit` | 0.034 | 0.127 | 否 |
| `sp.glm`（Poisson） | 0.023 | 0.063 | 否 |
| `sp.poisson` | 0.023 | 0.063 | 否 |
| `sp.nbreg` | 0.023 | 0.063 | 否 |
| `sp.panel`（FE） | 0.039 | 0.075 | 否 |
| `sp.hdfe_ols` | 0.040 | 0.094（聚类） | 否 |
| `sp.feols` | 0.040 | 0.071 | 否 |
| `sp.fast.feols` | 0.040 | 0.071 | 否 |
| `sp.fast.fepois` | 0.026 | 0.057 | 否 |
| `sp.iv` | 3.29 | 7.32 | 否 |
| `sp.tobit` | 0.111 | 0.111 | 是 |
| `sp.ppmlhdfe` | 0.056 | 0.056 | 是 |

12 个入口的默认标准误比稳健标准误小 2 到 4 倍。`sp.tobit` 和 `sp.ppmlhdfe` 已经把权重当抽样权重。

处理效应类的入口不在这张表里。`sp.ipw`、`sp.aipw`、`sp.callaway_santanna`、`sp.sun_abraham` 等用的是影响函数或聚类方差，本来就对权重稳健，不存在这个问题。

**覆盖率。** 三项仿真（`tests/reliability/extreme_weights*.py`，共 42 个设计，每格 2,000 次）给出了默认区间在抽样权重下的实际覆盖率。

| 模型 | 名义 95% 区间的实际覆盖率 |
| --- | --- |
| OLS | 34% 到 78% |
| 固定效应 | 43% 到 81% |
| Poisson、负二项 | 14% 到 75% |

权重是精度或频数时，默认区间是对的（约 95%）。所以默认值本身没有错，错的是它对一半用户不适用，而且看不出来。

**已有的保护。** 这一轮给 9 个入口加了诊断。Kish 有效样本量低于样本量的一半且用的是默认方差时，会发出警告并指向稳健选项。`sp.logit`、`sp.probit`、`sp.glm`、`sp.iv` 还没有接。

## 三个方案

### A. 保持现状，补齐警告

把警告接到剩下的 4 个入口，把 67 条 schema 描述补全。不改任何接口，不改任何数值。

好处是零迁移成本。代价是保护只在"权重明显分散"时才触发，阈值是 Kish 比低于 0.5。仿真里 Kish 比约 0.4 的设计覆盖率已经掉到 78% 到 81%，而 0.4 到 1 之间没有模拟过，所以阈值以上的那一段是否安全并不知道，警告在那里是沉默的。警告也可能被忽略，脚本里尤其如此。

### B. 新增可选参数 `weight_type=`

给 12 个入口加 `weight_type={'analytic', 'frequency', 'sampling'}`，默认 `None`。

- 传了 `weight_type='sampling'`，方差自动换成稳健的，等同 Stata 的 `[pw=]`。
- 传了 `'analytic'` 或 `'frequency'`，行为和今天一样，但不再警告，因为用户已经表态。
- 不传，行为和今天完全一样，警告照旧。

好处是给了用户一个明确表态的办法，agent 也能在 schema 里看到这个选择。`sp.stata` 的翻译可以把 `[pw=]` 直接映射过去，现在它靠的是另加 `robust=`。代价是 12 个入口各多一个参数，schema、文档、card、测试都要跟着动，论文里若引用了签名也要核对。

### C. 强制声明

在 B 的基础上，不传 `weight_type` 就报错。走弃用流程：先警告一个小版本，再报错。

好处是从根上消除误用。代价是所有现存的带权重调用都要改，包括用户脚本、教程、复现包。`[aw=]` 的用户本来没有错，也要被迫改代码。这和"先对齐 Stata / R"的原则有摩擦，因为 R 的 `lm(weights=)` 和 `fixest` 都不要求声明。

## 影响对比

| | A | B | C |
| --- | --- | --- | --- |
| 改动的入口数 | 4（接警告） | 12（加参数） | 12（加参数并弃用旧用法） |
| 现有调用是否受影响 | 否 | 否 | 是，全部带权重的调用 |
| 现有数值是否变化 | 否 | 否 | 否 |
| 需要 MIGRATION 条目 | 否 | 否 | 是 |
| 警告阈值以上的权重是否受保护 | 否 | 用户表态后是 | 是 |
| 对论文的影响 | 无 | 签名多一个参数 | 示例代码要改 |
| 估计工作量 | 半天 | 两到三天 | 一周，外加一个小版本的缓冲期 |

## 我的建议

选 B，不做 C，并且现在就把 A 做掉。

理由有三条。

第一，A 是纯收益，没有理由等。4 个入口没有警告是个缺口，`sp.logit` 的默认标准误在例子里小了 3.7 倍。

第二，B 解决的是"用户想表态却没有办法"。现在用户只能靠记住"抽样权重要另加 `robust='hc1'`"，这正是 Stata 用 `[pw=]` 替用户做掉的事。一个可选参数不破坏任何现有调用。

第三，C 的代价落在没有犯错的用户身上。分析权重是 `weights=` 最传统的用法，强迫这些用户改代码换不来正确性上的任何收益。如果 B 上线后发现误用仍然普遍，再讨论 C 不迟。

关于时机。你之前定过一条规矩：论文投稿期间新增对外接口要有充分理由。B 给 12 个函数各加一个参数，属于这一类。JSS 稿件目前冻结暂停、计划近期投稿。稳妥的做法是 A 现在做，B 等 JSS 投稿之后再做，这样稿件锚定的版本里签名不变。

## 需要你决定的

1. A 是否现在做。我的建议是做。
2. B 做不做，以及放在 JSS 投稿前还是投稿后。
3. 如果做 B，参数名用 `weight_type` 还是别的。`sp.wild_cluster_bootstrap` 等四个函数已经有一个同名参数，含义是 bootstrap 权重的分布（Rademacher、Webb），和这里无关。为避免混淆可以叫 `weights_type` 或 `weights_as`。
