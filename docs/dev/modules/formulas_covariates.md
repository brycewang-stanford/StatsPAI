# 公式写法、协变量与处理变量的输入约定

> 从 CLAUDE.md §11 原样迁来（2026-10-17）。改动本领域的代码前先读完本文件；新的约定直接写在这里，CLAUDE.md §11 只留索引。

- **公式里的非标识符列名**：反引号 `` `a b` `` 在 `core/utils.py::r_formula_idioms` 里统一翻译成 `Q("a b")`（`backticks_to_q`），所有走 patsy 的入口自动支持；只读列名的解析器（IV、计数模型、固定效应、gam 的平滑项）用 `unquote_name` 取出列名。**新增公式入口时调用 `r_formula_idioms`，不要另认反引号**；对公式字符串做文本替换（如把 `- 1` 当去截距）必须避开引号内的内容，`sp.iv` 曾把 `Q("x-1")` 改成 `Q("x+ -1")`。
- **公式的 R 写法（同一轮）**：`y ~ .` 由 `core/utils.expand_dot` 在 `create_design_matrices` 入口展开（含 `|` 的 IV / 固定效应公式不展开）；布尔型因变量 `(earn > 0) ~ x` 在同一入口折成一列 0/1（patsy 会编成 `[False]` / `[True]` 两列）；有序 / 多项模型因变量外的 `factor()` / `C()` / `ordered()` 由 `multinomial._bare_outcome` 去掉。`sp.glm` 认 `cbind(成功, 失败) ~ x`（折成"比例 + 试验数作权重"，对数似然是未分组数据的，比 R 少一个二项系数常数）、`family='quasipoisson' | 'quasibinomial'`（即 `scale='x2'`）、`link='robit(dof)'`（Liu 2004，`robit(dof,unit)` 是书里方差为 1 的参数化）。
- **协变量列表里的分类变量（`core/_covariates.py`，2026-10-05 起）**：接收 `covariates=[...]` 的估计器用 `@_expands_categorical("covariates")` 装饰（已接入 ipw / aipw / match / psmatch2 / sbw / genmatch / optimal_match / cardinality_match / ebalance / overlap_weights / cbps / tmle / g_computation / dml / metalearner / auto_cate / policy_tree / dose_response / drdid / callaway_santanna、倾向得分诊断，以及 DiD 各估计器的 `controls=` / `covariates=`；森林家族走自己的 `forest/_grf_family.py::one_hot_covariates`：每个水平一列、不设基准，预测时未见过的水平报错）。`category` dtype、字符串列、`C(col)` / `i.col` 一律展开成哑变量（首水平为基准），普通整数列仍按数值处理；全数值的调用原样穿透，不复制数据。展开记录在 `model_info['covariate_expansion']`，对新数据预测时用 `apply_covariate_expansion` 重建（`sp.predict_cate` 已接）。**新增这类估计器时加装饰器，不要在函数里 `.astype(float)` 硬转**：此前 `category` 列被静默当成连续变量（书中第 5 章 AIPW 0.2757 对 0.2712），字符串列在 numpy 里报 `could not convert string to float`。
- **二值处理的校验**：只对 0/1 处理有定义的函数入口调用 `core._validate.require_binary_treatment`。`sp.balance_table` 遇到三臂处理曾返回一张 N=0 的空表，`sp.cate_eval` 遇到连续处理曾返回带标准误的 RATE。
- **公式里的 `I(x^2)`**：`core/utils.r_power_in_identity` 把 `I()` 内的 `^` 改写成 `**`（R 用户的写法；patsy 会把它当按位异或）。**新增任何直接调用 patsy `dmatrix` / `dmatrices` 的入口都要先过这个函数**，否则同一个公式在不同估计器里一个能跑一个报 `xor`。`I()` 之外的 `^` 保持 patsy 的交互展开语义，不动。
- **公式里的 Stata 写法（`core/_stata_formula.py`，2026-10-19 起）**：`r_formula_idioms` 把整项的因子变量写法（`i.g`、`ib2.g`、`c.x`、`1.post`、`a#b`、`a##b`、`c.x#c.x`、`c.(x z)#i.g`）交给翻译器的 `_stata.py::translate_fv_terms` 译成 patsy 项——与 `sp.from_stata` 是**同一份实现**（基准水平、交互保留哪些格子、`c.x#c.x` 是平方、缺主效应的因子交互拒绝），不要在公式层另写一套。只认**整项**：`i.g*x` 这类把 Stata 写法塞进 patsy 运算符的项、残留的 `#` 一律拒绝并给出正确写法。时间序列算子（`L.x`、`L2.x`、`F.x`、`D.x`、`L(1/3).x`）需要数据：`create_design_matrices` 读 `sp.xtset` 存在 `df.attrs` 里的面板声明，按 `utils/tsops.py` 计算成 `x_L1` / `x_D1` 列（与 `sp.stata` 同名）放进数据副本；没有声明、或数据里已有同名列，拒绝。不经过 `create_design_matrices` 的解析器（fixest、IV、面板等）在 `r_formula_idioms` 里遇到 `L.x` 拒绝并提示先用 `sp.lag` 建列。引号内（`Q("L.x")`）不动。系数参照 Stata 18（`tests/test_stata_formula_syntax.py`）。**fixest 公式竖线后的固定效应部分不翻译**（`r_formula_idioms(fixest_fe=True)`，`sp.feols` / `fepois` / `feglm` 三处都传）：那里的 `i.f#c.x` 是 reghdfe 的吸收斜率，交给 fixest 层读；变斜率路径（`_feols_varying_slopes` → `sp.hdfe_ols`）拿的是**原样公式**，它的解析器自己认 `i.f` / `c.x` / `ib2.f` / `i.f#c.x`，不认 patsy 的 `C()`。2026-10-19 曾把 `| county + i.pref#c.year` 译成 `C(pref):year` 而报 SyntaxError（`tests/test_varying_slope_loud_failure.py` 两侧都有测试）。
- **生成项里的整数列（`core/_formula_dtypes.py`，2026-10-21 起）**：patsy 按列的存储类型计算 `I(age**3)`、`np.power(x, 2)` 这类项，numpy 整数运算溢出不报错。此前 `_widen_narrow_integers` 把 int8 / int16 / int32 放宽到 int64，小值没事，但 Stata `long` 存的人口（两三百万）立方后仍溢出 int64，普通 int64 列也一样（`sp.regress("y ~ I(pop**3)")` 系数错到第一位）。现在 `_coerce_string_extension_dtypes(data, formula)` 带上公式（字符串或 patsy `DesignInfo`）时，`float_generated_term_columns` 把**生成项读到的**整数列转成 float64；裸列和 `a:b` 交互 patsy 本来就按浮点算，`C(g)` 读的列保持整数（否则水平名变成 `T.2.0`），同时出现在 `C()` 和生成项里且绝对值 ≥ 2^21 的列告警。`warn_wrapped_integer_columns` 对公式用到的窄整数列（int8 / int16 / int32）在取值同时接近类型两端（超过 90%）时告警，这是用户自己在窄类型里算过乘方后回绕的样子。已接入 `create_design_matrices`、`evaluate_formula_expression`、DiD 协变量公式（CS / drdid）、`panel` / `iv` / `mlogit` / `svy` 的公式路径，以及 `regress` / `glm` / `ridge` / `gam` / mcmc / conformal 的 `predict(newdata)` 与 margins。**新增直接调 patsy 的入口时把公式传给 `_coerce_string_extension_dtypes`**。`sp.feols` / `fepois` / `feglm` 的 fixest 公式不是 patsy 语法，由 `fixest/wrapper.py::_float_generated_fixest` 在顶层 `|` 处切开、只读含 `~` 的部分（主方程与 IV 第一阶段，固定效应部分不动），`i(f, ...)` 当作 `C(...)` 保持整数水平名（`rel::-2`），`sw()` / `csw()` 的参数逐个读，再交给 `float_generated_code_columns`（2026-10-21）。证据：`tests/test_formula_integer_overflow.py`（int8 / int16 / 大值 int32 / int64 与 float64 结果到 1e-10）。
