# MCP 服务器与随包 skill

> 从 CLAUDE.md §11 原样迁来（2026-10-17）。改动本领域的代码前先读完本文件；新的约定直接写在这里，CLAUDE.md §11 只留索引。

- **`agent/mcp_server.py`（`statspai-mcp`，2026-10-14 一轮）**：服务器给每个工具注入的十个公共参数（`data_path` / `data_id` / `result_id` / `detail` 等）在 `_common_argument_schemas` 里**每个只写一句**，长说明只在 `statspai://arguments` 资源里出现一次（`common_arguments_reference`）；改长任何一句都要乘以工具数，`tests/test_mcp_tool_list_budget.py` 按字节卡 `curated` / `core` 两档（此前这十个参数占 `tools/list` 的三分之二，146 KiB 里的 97 KiB）。`data_columns` / `data_sample_n` 所有工具都接受，但只在数据工具和 `call_function` 上列出。传输有两个：stdio（`serve_stdio`）与 Streamable HTTP（`_http_transport.py`，仅标准库）；两者共用 `handle_request` 与 `_admission_refusal`，进度通知经 `_bind_progress_sink` 按线程路由，**新增传输不要另写一套准入或进度逻辑**。HTTP 下非回环地址没有 `STATSPAI_MCP_HTTP_TOKEN` 就拒绝启动，这条不要放宽；句柄是进程级的，不按会话隔离，文档里已写明。`STATSPAI_MCP_STATE_DIR`（`_state_store.py`）把句柄落盘：文件是带签名的 pickle，目录必须只属于服务器用户，别人可写就拒用并告警，**不要**改成静默接受；LRU 淘汰只释放内存，TTL 过期和显式删除才删盘上的副本；另一版本写的条目读到即丢。`STATSPAI_MCP_WORKERS` 默认仍是 1：线程模式下估计器共享 `warnings` 过滤器等进程级状态，`runtime_warnings` 会串到别的调用上，**不要**为了吞吐把默认值调大。`completion/complete` 只覆盖资源模板变量与 prompt 参数，MCP 协议没有工具参数补全。真实模型的行为评测仍按 `docs/dev/review_backlog.json` 的 S2 关闭（要先做 OSF 预注册），不要为了验证 schema 改动先跑一轮 smoke。**协议是 dual-era（2026-10-16 起）**：`_meta` 里带 `io.modelcontextprotocol/protocolVersion` 的请求或 `server/discover` 走 `_protocol.py` 的无握手路径（MCP 2026-07-28：校验 `_meta`、`-32022` / `-32602`、结果加 `resultType` / `serverInfo` / `ttlMs` / `cacheScope`），`initialize` 仍走握手路径（2025-11-25 及更早）。新协议的规则**只加在 `_protocol.py` 和 `handle_request` 的那一个分支里**，方法处理函数两代共用，不要在处理函数里判断协议版本；握手路径的返回不加新协议字段。新协议下不得向客户端发请求（sampling 由 `_protocol.in_modern_request()` 关掉），HTTP 的 `Mcp-*` 头校验在 `_protocol.header_mismatch`。规范在知识截止之后才发布，改动前先读 modelcontextprotocol.io 上的 2026-07-28 规范与 schema.ts，不要凭记忆。改了协议层之后用官方 SDK 实测：`scripts/mcp_sdk_interop.py`（在装了 `mcp` ≥ 2.3 的另一个 venv 里跑，stdio / HTTP × auto / 2026-07-28 / legacy 六种组合，ATT 必须一致；SDK 不是依赖，所以它是脚本不是测试）。`tools/list` 的 profile 过滤只用 `_curated_tool_names()`（静态名单），**不要**再调 `tool_manifest(curated_only=True)`：它为每个工具补验证等级，会加载整个注册表（冷启动 3 秒）。`statspai mcp doctor` 探测解释器时去掉本 shell 的 `PYTHONPATH`、叠加配置里的 `env`、在 home 目录下运行，否则开发检出会让所有解释器看起来都是最新版。根目录 `server.json`（MCP Registry）的版本由 `release_gate.py --fix-census` 同步，发布到 registry 是对外动作，须当次授权。
- **随包 skill（`agent/_skill/`，`statspai skill install`）**：闸门 `validate_api_claims.py` 有四层，前三层（名字存在、参数能绑定、结果属性）只证明示例「写得出来」，第四层 `--run` 才把 quick-path、verified-skeleton、三条 pipeline 和 export 的代码块在闸门自带的合成数据上按文件顺序实际执行。**改了这几个文件里的示例，或改了示例调用的函数的取值校验之后，跑 `statspai skill validate --run-only <文件>`**（每个文件几分钟，`pytest -m slow tests/test_skill_package.py` 是同一件事）。2026-10-14 加这一层时，前三层全绿的 skill 里查出九处跑不通或语义错误的示例：`sp.oster_bounds(r_max=1.3)`（R² 不能大于 1，应为 `"1.3*r2"`）就在「verified skeleton」里；`sp.bjs_pretrend_joint` 传了 CS 结果和 cohort 列；把 TMLE 的风险差、OLS 的工资系数当作风险比传给 `sp.evalue(measure="RR")`；`first_treat_year > 2008` 把编码为 0 的 never-treated 整组删掉。跑不了的块（要 torch、要 LLM 客户端）用 ```` ```python no-run ```` 标记，仍参加绑定检查，数量由 `MAX_NO_RUN_BLOCKS` 封顶，不要用它绕过一个报错的示例。合成数据的列名跟文档里的 running example 走，文档新用到一列就在 `_worker_panel` / `_ehr_cohort` / `_uplift_experiment` 里补上。已安装的 skill 是一份拷贝，不随 `pip install -U` 更新：`statspai skill status` 报 stale 时用 `statspai skill install --force`。
