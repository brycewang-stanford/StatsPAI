# Stata 翻译（sp.from_stata / sp.stata）

> 从 CLAUDE.md §11 原样迁来（2026-10-17）。改动本领域的代码前先读完本文件；新的约定直接写在这里，CLAUDE.md §11 只留索引。

- **`agent/_translation/`（`sp.from_stata` / `sp.stata`）**：处理函数只按**全称**读选项；缩写（`r` / `cl()` / `a()` / `vce(cl id)`）、前缀（`qui` / `eststo:` 剥掉，`by` / `svy` 拒绝；`jackknife` / `bootstrap` 前缀与 `vce(jackknife)` / `vce(bootstrap)` 自 2026-10 起由 `sp.stata` 在 `_stata_resample.py` 里重抽样执行——命令自带这类方差的如 `sdid` 不经过它；`sp.from_stata` 单行翻译仍拒绝前缀）、宏（拒绝）由 `_stata_options.py` 在处理函数之前统一处理，**不要**在各处理函数里再认缩写。任何选项只有三种去处：进调用、进 `untranslated_options`（附 note）、进 `ignored_display_options`；`sp.stata` 遇到未翻译的选项就拒绝执行。`if` / `in`（2026-10 起）由 `sp.stata` 按 Stata 的缺失值规则应用（缺失值大于任何数，`if x > 0` 会保留 `x` 缺失的行），算不出来的表达式（`e(sample)`、字符串函数）才拒绝；`sp.from_stata` 只翻译单行、手里没有数据，仍把限定条件放进 `unapplied_sample`。数据步（`generate` / `replace` / `keep` / `drop` / `sort` / `mvdecode` / `encode` / `preserve` / `restore` / `predict` / `scalar` / `display`）在 `_stata_datastep.py`，表达式在 `_stata_expr.py`（封闭文法的递归下降解析器，**不许**用 `eval`；新增函数要按 Stata 文档的缺失值语义写并补 `tests/test_stata_expr.py`），时间序列算子 `L.` / `F.` / `D.` 在 `_stata_tsops.py`（按 `tsset` / `xtset` 的时间变量在面板内取滞后，不是行位移）。`generate` 默认存单精度，与 Stata 一致，这是回放 log 能对到最后一位的前提。新增或改动处理函数时，读到的选项值若解析失败要记入 `untranslated_options`（禁止 `except: pass`），且 `python_code` 必须与 `arguments` 是同一个调用——`tests/test_stata_translation_grammar.py` 的两条不变式（加选项必留痕迹；代码与参数一致）会拦。目标函数默认值与 Stata 不同时把 Stata 的默认写出来（`csdid` 的 `base_period='varying'`、`xtabond` 的 `robust=False`）。`replace` 按 Stata 的顺序语义执行（2026-10 起）：表达式引用被替换变量更早的行（`x[_n-1]`、`L.x`、`x[1]`）时看到的是已更新的值，由 `DataSteps._replace_in_order` 处理：能把表达式改写成"只依赖本行各列"的（`_row_local`：`_n` / `_N`、其他变量的下标、随机数各物化成一列）走 `_replace_row_by_row`，只重算读到了变动行的那些行，链多长都是每环一次小求值；含"对自身早先行的 running `sum()`"的走 `_replace_in_row_order`（按行顺序，先判条件，未选中的行不推进累加）；改写不了的（`sum()` 套 `sum()`）才整列逐轮求不动点，链长超过 20,000 行拒绝。**`sum()` 只在命令选中的行上累加**（`gen s = sum(x) if d`）：数据步先定下 `if` / `in` / `by` 选中的行，经 `stored["_sum_rows"]` 交给求值器，新增会求值表达式的数据步要沿用 `_evaluate_assignment`。`L.x` 生成的列登记在 `DataSteps.ts_derived`，每次被引用都按当前数据重算，**不要**再按"列已存在就复用"处理。跨行的语法（`///` 续行、注释、`#delimit`、文本定义的 `global` / `local` 宏、`xtset` 的面板声明）在 `_stata_script.py`，只由 `sp.stata` 使用；只有"读得出来"的才解析：未定义宏、扩展宏函数（`local n : word count ...`）、`syntax`、`mata` 拒绝。**2026-10 起循环与计算宏会执行**（`_stata_flow.py`：`forvalues` / `foreach` / `while` / `if … else` 块、`local x = exp`、`` `=exp' ``、`tempvar` / `tempfile`、带 `args` 的 program），做法与 Stata 相同——把块体收到配对的 `}`，每轮设好循环宏后逐行交回会话，所以块体里的命令走的仍是同一套逐行翻译与拒绝规则，循环本身不引入新的语义。多数据集命令（`save` / `use` / `append` / `merge` / frames）在 `_stata_multi.py`，**不读写磁盘**：`save` 只在会话里留一份，外部数据集经 `sp.stata(..., files={名: DataFrame})` 传入；矩阵（`J()` / `e(b)` / 逐格赋值 / `svmat`，以及和、积、转置、`inv()` 这类表达式）在 `_stata_matrix.py`，其余矩阵函数（`cholesky` 等）拒绝；`egen` 在 `_stata_egen.py`。这些模块里每条语义都对照过真 Stata（见 `docs/dev/2026-10-04-clarke-applied-microeconometrics-review.md`），新增函数照此办理：先在 Stata 里跑出答案，再写实现。`python scripts/stata_corpus_scan.py <目录>` 是探测器：拿一批 do 文件看翻译覆盖率，按"出现在几个项目里"排序（它只回答"翻译了没有"；手里有 Stata log 时用 `python scripts/stata_log_replay.py <log> --data <dta 目录>` 回答"数字对不对"，逐个对照 log 里打印的每个系数、标准误、检验统计量——2026-10 用 Stock & Watson 4E 的 13 份 log 查出语料扫描报告 97.6% 忠实翻译的同一批文件里，稳健 probit / logit 的标准误和其后的 Wald 检验全是错的小样本因子）；修复要依据 Stata 文档、用合成命令测试，并在没参与修复的 do 文件上复查，**不要**照着某篇论文打补丁，也不要为只出现在一篇论文里的用户命令新增 `sp.*` 函数。2026-10 用 12 篇复现包的语料查出：修复前只有 12.9% 的估计语句能原样正确翻译，28% 是静默错误。
- **`sp.stata` 的数据管理 / 描述统计 / 抽样 / 编程层（2026-10 Kohler-Kreuter 一轮新增）**：数据管理命令在 `_stata_manage.py`（`recode` / `xtile` / `destring` / `levelsof` / `assert` …），描述与抽样在 `_stata_describe.py`（`tabulate` 全套选项、`mean` / `proportion` / `total` / `ratio`、`svyset` + `svy:`），表达式函数在 `_stata_functions.py`（字符串按**字节**计，`u*` 函数按字符），`margins` 的网格与因子水平在 `_stata_margins.py`，估计后命令在 `_stata_postrun.py`（`predict` 的影响统计量、`estat gof`、`lrtest`、`e(sample)`），宏与 `syntax` 在 `_stata_macro.py`。新增命令往对应模块加，不要再塞进 `_stata_session.py`。四条容易踩的约定：(1) **扩展缺失值**——数据里 `.a`–`.z` 与 `.` 都是 NaN，session 用 `stored['ext_missing']` 记录哪些变量可能含扩展缺失（来源：`attrs['_ext_missing']`、`__miss` 伴随列、缺失码标签、session 内赋值），在这些变量上 `x == .` / `x != .` / `x > .`、`by`、`tabulate, missing`、`collapse, by()` 一律拒绝（Stata 里 `.a != .` 为真、每种缺失各成一组），`missing(x)` / `x < .` / `x >= .` 照跑；新增会按缺失值分组或比较的命令时要接上这道检查。(2) **`mean` 族的方差**——无权重无聚类时 Stata 把 `over()` 各组当作独立的简单随机样本（`s/√n`，`proportion` 用 `√(p(1-p)/n)`，`total` 用 `√n·s`）；有 pweight / cluster / svy 时才是线性化方差，后者与 `sp.svydesign` 共用 `_design_vcov`。svy 默认 `singleunit(missing)`：存在单 PSU 层时标准误为缺失，不要替用户改成 certainty。(3) **`e(sample)`** 按「内存里那个 DataFrame 对象」绑定，`sort` / `drop` 之后即失效并拒绝，不要改成按行号猜。(4) `levelsof` 对非整数只写 16 位有效数字（`%18.0g`），`float` 变量的 16.1 因此在循环里匹配不到自己——这是 Stata 的行为，照做。经典检验（`sp.ranksum` / `kwallis` / `spearman` / `ktau` / `ksmirnov` / `median_test` / `robvar` / `oneway` / `signrank`）在 `inference/rank_tests.py`，回归与 logit 的影响诊断（`sp.influence_measures` / `sp.logit_influence` / `sp.logit_gof`）在 `diagnostics/influence.py`；Stata 18 参考数由 `tests/reference_parity/_fixtures/kk_syllabus_reference.do` 在合成数据上生成，改动这些函数或对应翻译后重跑该 do 文件再跑 `test_kohler_kreuter_stata_parity.py`，**不要手改 `kk_syllabus_stata.txt`**。回放脚本新增了「表格逐数比对」（`BAG`）与 `display` 文本比对，新命令没有专用比较器时把命令名加进 `BAG` 即可。
- **`[pweight=]` 与方差、`dropped` / `complete`（2026-10-19 起）**：Stata 对多数估计命令把 `[pw=]` 当作 `vce(robust)`（`xtreg, fe` 是 `vce(cluster 面板变量)`），名单在 `_stata.py::_PW_IMPLIES_ROBUST`，每一项都在 Stata 18 上核对过「`cmd [pw=w]` 与 `cmd [pw=w], vce(robust)` 的 e(V) 相同」。`from_stata` 在命令没写方差选项时给它补上 `vce(robust)` 再交给处理函数，所以**方差映射只在处理函数里写一次**（它的 `vce(robust)` 怎么译，`[pw=]` 就怎么译），`_apply_weight` 不再自己猜 `robust=`。新增接受权重的处理函数要确认它的 `vce(robust)` 映射在带权重时也成立（`sp.hdfe_ols` 的稳健方差不带权重，所以带权重的稳健 `reghdfe` / `ivreghdfe` 走 `sp.feols(vcov='hetero', fixef_rm='singleton')`）。Stata 拒绝 `[pw=]` 的命令（`newey` / `prais` / `rdrobust` / `xtnbreg`）在 `_PW_NOT_ALLOWED` 里照样拒绝。两个翻译器的成功返回都带 `dropped`（调用没有带上的一切：选项 / 参数名，以及未应用的 `if` / `in`）和 `complete`（`dropped` 为空才为真），由 `_payload.py::mark_completeness` 统一生成；旧键 `untranslated_options` / `unapplied_sample` / `untranslated_arguments` 保留。命令名到 sp 函数的对照表就是 `_stata.py::STATA_COMMAND_MAP`（含各子模块的 `HANDLERS`）、`_stata.py::_UNTRANSLATED_GUIDANCE`（带 `statspai_functions` 的拒绝）与 `_r.py::R_FUNCTION_MAP`，`translation_coverage()` 由它们内省生成。一行翻译证明不了、但 `sp.stata` 能在数据上核对的前提（`eventstudyinteract` 的变量表是否恰为除 -1 外的全部相对期指示变量、`stcrreg` 的事件编码），处理函数把它记入 `untranslated_options`（`from_stata` 因而 `complete=False`），并在返回里放核对规格（`verify_relative_time` / `requires_codes`），由 `_stata_run.py` 在运行前核对，通过才把那一项移除。**不要在共享仓库里用 `git stash`**：stash 列表是所有 worktree 共用的，2026-10-19 一次 `stash` + `pop` 弹出了另一个窗口刚 stash 的改动。
- **多维聚类的 `reghdfe`（2026-10-19 起）**：`reghdfe ..., absorb(...) cluster(a b)` 译为 `sp.hdfe_ols(..., cluster_df='min')`。reghdfe 与 fixest 对多维聚类方差的每一项都乘 G_min/(G_min − 1)，`sp.hdfe_ols` 1.41 前的默认是每项各乘自己的 G/(G − 1)（`sandwich::vcovCL`，现为 `cluster_df='per_term'`），1.41 起默认就是 `'min'`；翻译仍显式写出 `cluster_df='min'`，不依赖版本。旧默认下第二维只有三个水平时标准误差 6%。在 Stata 18 reghdfe 6 上核对到 1e-8（`tests/test_stata_translation_pweights.py`）。没有 `absorb()` 时 `cluster_df=` 不可用，翻译只附一条说明。
- **`leebounds`（2026-10-19 起翻译）**：`_stata_extra.py::_h_leebounds` → `sp.lee_bounds(trimming='leebounds', se_method='analytic')`；`vce(bootstrap)` 默认 50 次（`leebounds` 的默认），`level()` 走通用的 `alpha`，权重因 `sp.lee_bounds` 没有 `weights=` 而拒绝。执行等价测试在 `tests/test_stata_translation_extra.py` 末尾。
- **`med4way`（2026-10-19 起翻译）**：`_stata_extra.py::_h_med4way` → `sp.four_way_decomposition(vce='ml')`，只覆盖 `yreg(linear|logistic|poisson)` × `mreg(linear|logistic)`；`c()` 里的 `.` 表示取均值；`bootstrap` / `casecontrol` / `yregoptions` / `mregoptions` 拒绝。
- **数据层的单一实现（2026-10-19 起）**：`reshape` / `collapse` / 时间序列算子的计算在 `utils/reshape.py`、`utils/collapse.py`、`utils/tsops.py`，即公开的 `sp.reshape` / `sp.collapse` / `sp.xtset` / `sp.lag` / `sp.lead` / `sp.diff`；`_stata_reshape.py`、`_stata_datastep.py::_collapse`、`_stata_tsops.py` 只做解析、`float` 精度与把 taxonomy 异常换成 `StataExprError(exc.message)`（消息逐字不变）。`egen` 同理（2026-10-20 起）：计算在 `utils/egen.py::egen_compute`（公开的 `sp.egen` 与 `_stata_egen.py::run_egen` 共用），`run_egen` 只做解析、按 `by g:` 分组求表达式（`_n` / `_N` 在组内计数）、单精度存储与异常转换。**改语义只改 `utils/` 那一份**，并在 Stata 18 上核对（参考数在 `tests/test_data_layer.py`）。公开函数保持双精度，单精度存储只是 `sp.stata` 会话的事。`sp.xtset` 把声明存在 `df.attrs['statspai_xtset']`（2026-10-20 起 `sp.stata` 在会话开始和 `use` 时读它，等于在片段开头写了那行 `xtset`，含排序；声明里的列不在数据中时告警并忽略，因为 pandas 会把 attrs 带到列子集上），与 Stata 一样接受时间变量有缺失的行（不参与描述），但算滞后时拒绝它们（Stata 对缺失时间的 `F.x` 会返回同为缺失时间那一行的值，属于怪癖，不复制）。`sp.stata(..., return_data=True)` 在 do 文件结束时若仍处于 `preserve` 状态，返回被保存的那份数据（Stata 18 实测：do 文件结束即恢复）。
- **`stteffects` 与 `didregress aggregate()`（2026-10-20 起翻译）**：`_stata_survival.py::_h_stteffects` → `sp.stteffects`，方程按位置读（`ra` 结果+处理；`wra` 再加删失；`ipw` 处理+删失；`ipwra` 结果+处理+可选删失，没有删失方程即 LAC）。只含常数的删失模型在 Stata 里写作 `(, weibull)`，空的 `()` Stata 报语法错，翻译也拒绝。`noconstant`（`sp.stteffects` 总带常数）、`gamma`、`hetprobit` 拒绝；`ipwra, atet` 翻译但把 `atet` 记入 `untranslated_options`（Stata 在全样本上平均，见 `survival.md`），所以 `sp.stata` 拒绝执行。事件变量照 `stcox` 的办法核对 0/1 编码。`didregress, aggregate(dlang)` 写出 `dlang_df='stata'`，否则区间与 Stata 不同；Stata 拒绝 `aggregate(dlang)` 与 `vce(cluster)` / `wildbootstrap` 同用，翻译也拒绝。执行等价测试复用已冻结的 Stata 参考（`stteffects_Stata.csv`、`didregress_dlang_Stata.csv`），外加 Stata 18 打印值的几行。
- **`xtregar` / `xttobit` / `xtintreg`（2026-10-20 起翻译）**：在 `_stata_panel.py`，面板声明与 `xtreg` 一样走 `i()` / `t()`（`sp.stata` 由 `xtset` 补上；`xttobit` / `xtintreg` 只读 `i()`）。`rhotype()` 的取值缩写按手册（`reg` / `tsc` / `th` / `nag` / `one`），`dw` 是默认、不写出。积分：两边都是自适应 Gauss-Hermite，近似的是同一个似然，`intpoints(#)` 照传，不写时用 sp 的 30 点（不比 Stata 的 12 点差）；`intmethod(ghermite)` 是非自适应、近似误差不同，进 `untranslated_options`（`sp.stata` 因而拒绝）。`ll` / `ul` 不带数（取样本最值）或给变量名时拒绝，与 `tobit` 相同；`xttobit` 不给任何界限时拒绝并指向 `sp.panel(method='mle')`。执行等价测试复用 `tests/fixtures/xtregar` 与 `tests/fixtures/xttobit` 已冻结的 Stata 18 数（`tests/test_stata_translation_xt_ar_censored.py`）。
- **`mmqreg` / `xtqreg`（2026-10-20 起）**：在 `_stata_panel.py`。`mmqreg` → `sp.mmqreg`，`q()` 只收一个数（多个分位数在 Stata 里有跨分位数的联合协方差，`sp.mmqreg` 一次一个，拒绝并提示逐行写）；小于 1 按比例读、大于等于 1 按百分数读（Stata 18 上 `q(.5)` 与 `q(50)` 的 `e(qval)` 相同，与 `qreg` 一致）；`robust` / `cluster()` / `vce(robust|cluster)` 对应 `vce=`，默认 `gls` 不写出；`denopt()` / `dfadj` / `jknife`、其他 `vce()`、多变量聚类、权重、因子变量都拒绝；`nowarning` / `nols` 只影响显示。执行等价测试复用 `tests/fixtures/mmqreg` 已冻结的 Stata 18 数（`tests/test_stata_translation_mmqreg.py`）。`xtqreg` 整条拒绝：它的分位数系数标准误是另一种 GLS 形式（尺度矩不中心化），没有复现；`translation_coverage()` 里 `xtqreg` 的目标为空并列入 limitations；报错里给出的 `sp.mmqreg(..., vce='cluster')` 调用在测试里被实际执行，系数、`e(q)`、位置方程系数与 `xtqreg` 一致到 1e-10。
- **`drdid, dripw` 在重复截面上（2026-10-21 起）**：`_stata_did.py::_h_drdid` 对没有 `ivar()` 的 `dripw`（含 `rc1`）以及 `all` 写出 `variance_convention='reference'`，所以 `sp.stata` 回放打印的是 Stata 的标准误；附注说明 `sp.drdid` 的默认 `'delta'`（Sant'Anna-Zhao 2020 附录 B，1.40.0 起为默认）在倾向得分模型设定错误时才是渐近正确的标准误（蒙特卡洛覆盖率 0.95 对 0.81），去掉该参数即得。ATT 两种约定相同；面板与其他估计量不受影响。执行等价测试在 `tests/reference_parity/test_stata_did_commands_parity.py`（复用已提交的 `did_commands_Stata.json`）。
- **事件研究翻译的推断口径（2026-10-21 起）**：`eventstudyinteract` 译为 `sp.sun_abraham(..., parity='stata')`，fixest `sunab()` 译为 `parity='r'`（固定份额方差 + 聚类时 t(G−1)）。系数与标准误不变，变的是 p 值与区间，跟随被翻译的命令。今后新增的翻译若目标函数有 `parity=`，同样写出对应程序的值，这与「目标函数默认值与 Stata 不同时把 Stata 的默认写出来」是同一条规则。
- **`i.f#1.d` 的翻译（2026-10-28 起）。** Stata 把 `i.f#1.d`（`ibn.f#1.d`、`f#1.d`、`1.d#i.f` 同）编码为 f 的每个水平一列，不省略基准水平；`d` 是 0/1 时等于 `C(f):d`（`sp.regress`）/ `i.f#c.d`（`sp.hdfe_ols`），与 reghdfe 6.13.1 对到 1e-11（`tests/reference_parity/test_fv_level_one_parity.py`），并在 `semantics` 里写明"1.d 按 0/1 列读"。模型里同时有 `d` 本身时 Stata 因共线删掉**最后**一个水平，两种公式语法删第一个，同一拟合、系数不同，所以拒绝。`2.d` 等其它水平仍拒绝。单独的 `i.g#c.x`（没有 `x` 主效应）是每个水平一个斜率，翻成 `sp.hdfe_ols` 的 `i.g#c.x`；有 `x` 主效应时 Stata 省略基准水平，与 `i.g:x` 相同（已核对）。
