# 处理效应（TMLE、IPW/AIPW、匹配、反驳检验）

> 从 CLAUDE.md §11 原样迁来（2026-10-17）。改动本领域的代码前先读完本文件；新的约定直接写在这里，CLAUDE.md §11 只留索引。

- **`tmle/`（2026-10 Schuler-van der Laan 一轮）**：`sp.tmle` 的 `estimand` 必须校验（1.39 前除 `'ATE'` 以外的任何字符串都静默返回 ATT，`'ate'` 也是）。三条约定：(1) EY1 / EY0 / RR / OR 只在 `fluctuation='per_arm'` 下才是 TMLE（单个 clever covariate 只解差值那一个方程），所以这四个 estimand 强制 per-arm，`result.detail` 也只在 per-arm 时给出；RR / OR 的区间在对数尺度上构造，`se` 是自然尺度的 delta 法。(2) ATT 只扰动 Q、g 不动，写成估计方程的形式，但因为扰动恰好解了 `sum H (Y - Q*) = 0`，它**就是**处理组上 `Q*(1,W) - Q*(0,W)` 的 plug-in 均值，EIF 均值恰为零（`test_r2_teffects_parity.py` 的恒等式）；ATC 是同一计算把两臂对调。**不要因为"它不更新 g"就以为它不是 TMLE 而去改默认算法**（这一轮中途这么做过，查到上面那条恒等式后撤回，ATT 的数值没有动）。R `tmle` 的 ATT / ATC 是另一种同样合法的 TMLE（小步长路径同时更新 g、先丢掉 `g < min(g | A=1)` 的对照、按似然停止），两者只差零点零几个标准误，不是 parity 行。(3) 每个结果的 `model_info['influence_function']` 均值必须为零，这是 `tests/test_tmle_targeting_properties.py` 对所有 estimand 的断言，新增 estimand 要过这条和"饱和模型下等于分层估计量"那条。与 R `tmle` 2.1.1：均值、差、RR、OR 在共享初始拟合下对到 1e-11（含权重与聚类）；带权重时它的 log OR 影响曲线没有中心化（方差偏大 0.3%–2%，可由我们的量加回 `w(1/(1-EY1) - 1/(1-EY0))` 重建到 1e-9），那是参考实现的问题，不要去对。弱重叠下（9% 的真倾向得分在 [0.025, 0.975] 之外）点估计无偏，是影响函数标准误偏小 15%–21%，ATT 的 95% 区间只覆盖 81%；**换截断界没有用**（试过 1e-6 到 0.1，0.74–0.87），交叉拟合到 0.84，整体重拟合的 bootstrap 到 0.90，所以补救办法是 `se_method='bootstrap'`（`tmle/_bootstrap.py`，按行或按簇重抽、每次连 Super Learner 一起重拟合，不接受外部给定的 Q / g1W；与 `fold_indices` 同用时同一行的各个副本留在该行原来的折里），不要去加自适应截断。**也不要加"把倾向得分拟合在结果模型预测值 (Q0, Q1) 上"这条捷径**：结果模型正确时它能把标准差降 17%–21%，结果模型漏掉一个混杂时偏差 1.47、覆盖率 0（双稳健性整个丢掉）；正规的 C-TMLE 是 `sp.ctmle`（`tmle/collaborative.py`，按 van der Laan-Gruber 2010 独立实现，R `ctmle` 是 GPL、只当黑盒）：贪心与交叉验证的准则都是 `RSS + var(IC)`（CV 里再加 `n·bias²`）——**贪心那一步也必须带方差惩罚**，只用 RSS 时进入顺序在损失平坦处与 R 不同；带上之后 6 个夹具的进入顺序与每一步的估计量对到 3e-9（T2）。CV 选第几步无法逐行对照，原因已定位：`ctmleDiscrete` **完全忽略 `folds` 参数**（固定种子时传什么划分结果都一样），所以只能比分布——60 个随机划分上各步的 CV-RSS 均值一致，200 个数据集上偏差 / 标准差 / 平均选中步数一致，记为 S。R 默认的 CV 准则只有 RSS（它报告的 `penlikelihood` 里没有惩罚项），对应 `penalty='search'`；我们默认 `'variance+bias'`，在正确设定下标准差 0.093 对 0.103。`order=` 是预排序（scalable）变体，6 条序列对到 8e-10。**重启规则**：一步必须同时降低带惩罚的准则**和**裸 RSS，任一不降就从当前靶向拟合重启（只看准则时，方差略小而 RSS 略大的候选会被误判为改进，两条序列因此差 5e-6；是穷举 8 种重启模式定位出来的，不要改回只看准则）。模块叫 `tmle/collaborative.py`，**不要改回 `ctmle.py`**（与函数同名后测试取不到私有部分）。三条不要动的结论：(1) 影响函数标准误偏小 20%–40%（R 也一样），推断用 `se_method='bootstrap'`；(2) **只做 ATE**，协同式 ATT 试过，结果模型漏掉效应异质性时偏 −0.17，已撤回，不要加回来；(3) 序列上的 RSS 不单调（扰动最大化的是 Bernoulli 似然），不要写成单调。`sp.aipw(outcome_model='logit' | 'probit' | 'poisson')` 与 Stata `teffects aipw (y x, logit | probit | poisson)` 对到 5e-9（堆叠三明治里每一臂用三样东西：得分乘子 `s`、Hessian 权重 `h`、`v = dmu/deta`；logit / poisson 是典则联结，`s = Y - mu`、`h = v`；probit 用它自己的得分 `lam = (Y - mu) phi / (mu (1 - mu))` 和**观测** Hessian `lam (lam + eta)`，换成期望 Hessian 就对不上 Stata）。已知的处理概率走 `sp.tmle(g1W=标量)` / `sp.aipw(propensity=)` / `sp.ipw(propensity=)`；`sp.dml(model='irm')` 有意没加。给 `tmle` 维护者的说明在 `docs/dev/2026-10-07-tmle-weighted-odds-ratio-note-draft.md`，2026-10-07 已由 Bryce 邮件发出，尚无回复；对方若修了，重生 `tmle_parameters_R.json` 后要删掉“带权 OR 方差不一致”那条测试的豁免。`sp.causal_gap` 是书里第 2.3 节的 critical causal gap（`diagnostics/causal_gap.py`），只做区间端点到 null 的距离，不要往里加任何混杂模型。
- **`matching/full.py`（`sp.full_match` / `sp.match(method='full')`，1.39 起）**：最优全匹配按「二部图最小费用边覆盖 = 约化收益 `min_i + min_j - c_ij` 上的最大权匹配 + 未覆盖点各取最便宜的边」精确求解，一次 `linear_sum_assignment`，**不要**换成网络流库或启发式。零距离并列时要删掉两端都已被覆盖的边（否则连通分量不是星形）。证据是小问题上穷举全部边覆盖；optmatch（GPL，黑盒）把距离按容差取整，默认容差下总距离比我们大，收紧到 1e-9 后总距离一致但匹配集合仍不唯一，估计值差 1e-3——**只能写「总距离不高于 optmatch」，不能写估计值与 MatchIt 对齐**。给定匹配集合时估计量与按集合聚类的 SE（`matched_set_effect`）等于 `lm(weights=)` + `sandwich::vcovCL`，1e-9。
- **`robustness/refute.py`（`sp.refute`）**：估计器无关的反驳检验，按 `estimator(data, y=, treat=, covariates=, **kw)` 调用。p 值问的是"重跑结果是否以应有的值为中心"，不是"是否接近"；`n_simulations < 2/alpha - 1` 时永远拒绝不了，直接报错。打乱结果变量会把混杂一起打掉，是弱检验；能抓出漏调整的是 `outcome_function=`（保留混杂的哑结果）。它们都查不出未观测混杂，文档里必须指向 `sp.sensemakr` / `sp.evalue`。
- **`matching/`**：`sp.match` 有放回匹配默认 `ties='all'`（1.39 起；Stata `teffects`、R `Matching::Match` 的做法，估计不依赖行序，Lalonde 上与 `teffects psmatch` 逐位一致）。`ties='first'` 是 `psmatch2` 不带 `ties` 选项时的规则，`sp.psmatch2` 显式传它；新写的内部调用要想清楚自己要哪一个，不要依赖默认。
- **`sp.ipw(se_method='sandwich')`**：1.39 起也覆盖 `normalize=False`（HT）和 `trim > 0`。被截断的得分对系数的导数为零（估计量里它就是常数），倾向得分方程的 score / Hessian 用**未截断**的拟合值。没有第三方包算这个方差，证据是测试里独立写的数值微分堆叠 M 估计量（12 种组合 1e-10）。
- **`sp.aipw(trim=)`（1.39 起）**：倾向得分截到 `[trim, 1 - trim]`，默认 0.01；`trim=0` 是教材公式。截断数必须在 `_fit_propensity` **之外**统计（1.39 前在拟合函数里先截了一次，外层再数，`n_propensity_clipped` 恒为 0，警告永不触发）。新写的估计器若截断倾向得分，要报告截断数并告警。
- **`matching/`**：倾向得分的 logit / probit 拟合只有一份，在 `matching/_binary_fit.py`（标准化设计上做 Newton，冗余协变量按 Stata 的做法剔除、系数记 0，未收敛发 `ConvergenceWarning`）。**不要**在别处再写一个直接对原始列 `np.linalg.solve` 的 IRLS：Hessian 奇异时它不报错，旁边有 `re74^2` 这种 1e9 量级的列时误差会漏进得分（2026-10 邱嘉平教材第 6 章，ATT 偏 4%；包内 Lalonde 数据加一个重复虚拟变量可复现，605.80 对 Stata 468.10）。匹配用的得分**不截断**，相同协变量的行用 `_index_by_row` 只算一次（并列靠位级相等判断）；比较"距离相同"时两边必须出自同一个数组——`cutoff**2`（C 库 pow）与 numpy 的 `d**2` 约六百个数里有一个差最后一位。`sp.pscore` 是 Becker-Ichino 的分块与平衡性检验（Stata `pscore`），`attnd` 翻译成 `sp.psmatch2(ties=True)`，`common_support='treated'` 是它们的 `comsup`（按处理组得分范围剔对照），与 psmatch2 的 `common`（`'minmax'`）不是一回事。`atts` 是 `sp.match(method='stratify', strata=<块列>)`，`attk` 是 `sp.psmatch2(method='kernel', kernel='normal', bwidth=0.06)`；`attr` 是 `radius_weights='pairs'`（每个半径内的配对算一次，按"半径内有几个处理个体"给对照加权）：只为复现已有结果而提供，**默认值必须保持 `'treated'`**（psmatch2 的半径匹配），翻译时带说明。`sp.heckman` 两步法的 ρ̂ 出了 [-1, 1] 时按 Stata 截断并告警，不要把 ρ̂²>1 直接代进方差公式。Stock-Yogo 临界值在 `diagnostics/_stock_yogo.py`，是从 Stata `estat firststage` 的 `r(mineigcv)` 实跑导出的，**不要手改**。
- **`matching/residual_balance.py`（`sp.residual_balance`）**：目标函数是 `(1-zeta)·Σγ² + zeta·‖失衡‖∞²`（从 balanceHD 的输出反推并核对过：zeta 越大失衡越小）。求解走对偶（每个协变量一个变量，L-BFGS-B，对偶变量以 `2a/n` 为单位，否则 zeta 接近 0 或 1 时病态），再用活跃集迭代精确解 KKT；活跃集不收敛时退回拟牛顿点。balanceHD 的 quadprog 路径没有解到最优（它的目标值在每个配置上都比我们高 1e-10 到 1e-8），所以权重只对到 1e-6，测试容差 2e-5 是参考求解器的精度，**不要**为了对上而放松我们的求解。balanceHD 是 GPL-3，只当黑盒。标准误以协变量为条件（样本平均效应），`outcome_model='none'` 时没有标准误（残差里还有协变量信号，且高维下纯加权估计有偏）。
- **`sp.match(exact=, covariate_calipers=, mahvars=)`（2026-10-19 起，`matching/_pair_constraints.py`）**：三个选项都只是"哪些处理-对照对允许配"的规则，禁止的对距离记为 `inf`，匹配逻辑本身不动；因为排序打分搜索和 k-d 树看不到距离矩阵，有约束时这两条快路径关掉，走逐行定义（`_nn_match_row`）。语义照 MatchIt 4.7.2 `matchit2nearest`：`exact` 在各格内配（格里没有对照的处理单位不配、计入 `n_treated_without_exact_control`）；命名卡尺在 `caliper_scale='sd'` 下乘该变量全样本 `sd()`（n-1），与 `std.caliper=TRUE` 一致；`mahvars` 用合并组内协方差的马氏距离配，`caliper` 改为施加在倾向得分上，`m_order='largest'` 仍按得分排。8 个配置与 MatchIt 的配对逐行一致（`test_matchit_constraints_parity.py`）。**`mahvars` 的得分卡尺必须在建距离矩阵之前设好**：不放回匹配一次性建完整矩阵，晚设就整个漏掉（实现时踩过，339 对变成 394 对）。这三个选项下拒绝 `se_method='abadie_imbens_2016'`（它假定只按得分配）。
- **`sp.ebalance(estimand=, base_weights=)`（2026-10-19 起）**：ATT 把对照配到处理组矩，ATC 反过来，ATE 两臂各自配到合并样本矩；基础权重只是熵的参照 `q`，目标矩不加权（WeightIt `base.weights` 的语义）。方差在 `matching/_ebalance_se.py`，一套堆叠方程覆盖三种 estimand 与基础权重，ATT 数值与旧实现逐位一致。`dof_adjust` 是 Stata 的约定，只对 ATT 定义。
- **`sp.bcf` 不是 BCF**：随机森林 + 梯度提升 + bootstrap，没有 BART 先验和后验。每次调用发 `BCFApproximationWarning`，`method` 标签写明；真正的 BCF 是另一轮的事，**不要**悄悄改它的数。
- **`sp.dose_response` 的默认模型保留**（2026-10-19 测过）：线性混杂设计（n=1000、30 次）上默认 GBM 对 25-75 分位效应偏差 −0.13（真值约 1.9）、标准差 0.43、曲线从不单调；Hirano-Imbens 二次型（`LinearRegression` + `PolynomialFeatures(2)`）标准差 0.07 但偏差 +1.27，接近未调整斜率。所以不换默认，只在两个模型都取默认时告警并给 `curve_monotone`。
- **`sp.causal_forest` 的 `n_jobs`**：端到端逐位与线程数无关（`test_treatment_effects_oct19_fixes.py`），n=4000 时 `n_jobs=-1` 比默认 1 快约 3 倍。它是核心函数，默认值改不改由 Bryce 定。
- **`bounds/lee_manski.py`（`sp.lee_bounds`，2026-10-19）**：估计样本按 Stata `leebounds` v1.5 定义（`bounds/_lee_sample.py`）：处理或选择指示缺失、或被选中但结果缺失的行**整行**删掉并告警；指示变量必须是 0/1（`leebounds` 对 1/2 编码的处理变量不报错但下界会变，我们拒绝）。`selection=None` 等于不带 `select()`（结果非缺失即被选中）。`tight()` 下协变量缺失的行，`leebounds` 留在未截尾一臂的均值里、却不进任何格子，两种样本混用；我们整行删掉并在告警里写明，先删再跑两边一致（`test_lee_bounds_missing_Stata_parity.py` 的 `xdrop`）。`cieffect` 的区间：Stata 报告的数等于在 0.001 步长网格上取临界值所得（黑箱观测），我们解方程，区间最多差 0.001 个标准误，测试用重建网格做恒等式。**跟 Stata 比之前先确认两边读的是同一份字节**：`import delimited` 默认把结果存成 float32，`leebounds` 的阈值按 16 位有效数字取整（黑箱观测），遇到 float 数据时下界能移 0.01（2026-10-19 审计报的 0.1358 对 0.1304 就是这个，不是 bug），用 `asdouble` 或两边都转 float32。
- **`mediation/four_way.py` + `_four_way_engine.py`（`sp.four_way_decomposition`，2026-10-19 起支持非线性）**：四个分量统一写成反事实均值 `g(a, a') = E[mu(a, M_{a'})]` 的差，中介的期望取闭式（线性结果用 `E[M]`，对数线性结果用中介的矩母函数：正态 `exp(s mu + s^2 sigma^2/2)`，二值 `1 - p + p e^s`），对数线性结果再除以 `g(a0, a0)` 得到超额相对风险（`med4way` 的 `ereri_*`）。Delta 法的雅可比用复步求导（无截断误差），**不要**换成有限差分。logistic 结果按风险读，需要罕见结果（与 med4way / CMAverse 一致）。`vce='ml'` 等于 med4way（8 个设定，估计 5e-9、SE 6e-8；它的 `op_e` SE 本应等于 `p_cde` SE，有一个设定差 2e-6，是它的数值导数）；`vce='ols'` 的估计等于 CMAverse（1e-8）。**CMAverse 的 ERcde / ERintref 标准误在正态中介 + 对数线性结果下与 med4way 和我们都对不上**（比值约 2.8 和 0.8，其余分量一致），且它不计中介方差的抽样误差；med4way 与我们的解析推导一致，所以这是参考实现的问题，未上报（CMAverse 为 GPL，只当黑盒）。原型阶段用 statsmodels GLM 拟合时 SE 差 3e-6，那是 statsmodels 默认收敛容差，不是 med4way 的问题；引擎里的 Newton 迭代到系数不再移动。
- **`sp.ipw` / `sp.aipw` / `sp.tmle` 的 `design=`**：`design=`（复杂抽样设计，2026-10-19 起）只有一个方差入口：`survey/linearization.py::design_vcov`（= R `survey::svyrecvar`，含 strata / PSU / fpc / lonely-PSU / 校准），估计器只负责交出逐行贡献 `u_i`（`theta_hat - theta ≈ Σ u_i`，抽样权重已在里面；对均值归一的权重就是 `u/n`）。不要在估计器里再写一份 PSU 求和或 `G/(G-1)`。`design=None` 时代码路径与之前逐位相同；`design=` 与 `weights=` / `cluster=` / bootstrap 同用一律报 `MethodIncompatibility`。推断用 t(#PSU − #strata)（Stata `svy` 口径）。证据在 `tests/reference_parity/test_survey_causal_parity.py` / `test_survey_did_parity.py`（R survey 4.5，1e-14 量级）。 `ipw` 永远用堆叠三明治的影响行（`_ipw_sandwich_se(rows_only=True)`，`se_method` / `n_bootstrap` 不再起作用）；`aipw` 用所选 `se_method` 的影响行；`tmle` 的 `result.detail` 也走设计方差（`parameter_table(df=)`）。R 侧的参照是手写的堆叠估计方程 + 闭式 Jacobian（与 `numDeriv` 核对到 1e-10），再 `svyrecvar(-A^{-1} w ψ)`——Binder 线性化，不是把我们的公式抄一遍。
- **`sp.ltmle(design=)` / `sp.match(design=)`（2026-10-20 起）**：同一个 `design_vcov` 入口。ltmle 的贡献是 `IC / n`（IC 已除以权重均值，与 `weights=` 路径同一口径）；R 参照是两个**单一 regime** 拟合的 `IC$tmle` 之差（两 regime 拟合的 `r$IC` 是 MSM 参数化的，不是 ATE 的 IC，别拿来用），再 `svyrecvar`。行即 PSU、无层、无 fpc 时设计 SE 与 `weights=` 的 SE 逐位相等（有测试）。`sp.match(design=)` 只做最近邻 ATT/ATC：设计权重当 MatchIt `s.weights`，SE 是匹配样本回归 `y ~ d` 的线性化，匹配行作为全设计的一个 domain（R `svyglm(y ~ d, subset(design, matched))`，MatchIt 文档的做法），匹配权重视为固定；其他匹配方法没有影响函数，直接拒绝并指向 `sp.ipw / aipw / tmle(design=)`。
- **复制权重设计（`sp.svrepdesign` / `sp.as_svrepdesign`，2026-10-20 起）**：`survey/replicate.py` 是设计对象与方差公式（`scale * Σ rscales (θ_r - c)²`，`c` 为复制均值或 `mse=True` 时的全样本值；各 type 的 scale / rscales / mse 默认值、df = 复制权重的秩 − 1 都按 R `svrepdesign` 的输出核对过）；`survey/_replicate_refit.py` 是估计器侧的唯一入口：有 `weights=` 的估计器在函数第一行 `_args = dict(locals())` 后调用 `replicate_refit`，它用全样本权重和每个复制权重各拟合一次（零权重行**删掉**，不是留着），按结果类型（`EconometricResults` / `CausalResult` 含 `detail` 与 `event_study` 表 / `LTMLEResult`）装上复制协方差与 t(df)。新估计器要支持复制设计就照这个模式，不要自己写循环；没有 `weights=` 或带随机性（交叉拟合、bootstrap）的估计器由 `check_design` 统一拒绝。参考：R survey 4.5 + Stata 18（`test_survey_replicate_parity.py`）。Stata 的两处约定：BRR 的 df 报 #复制 − 1（R 与我们用秩 − 1）；`svy bootstrap` 除以 R（`scale=1/R` 复现）；Stata 不加 `saving(, double)` 时复制估计以 float 存储，e(V) 偏 1e-7，取参照时要加。R `withReplicates` 的函数里别把权重参数叫 `w`：`glm(weights=w)` 先在 data 里找列 `w`，静默用了全样本权重（生成参照时踩过）；数据里有名为 `t` 的列会让 `svyglm` 的复制方法报错。
- **`matching/weightit.py` + `_weightit_core.py` + `bal_tab.py`（`sp.weightit` / `sp.bal_tab`，2026-10-19 起）**：多类别与连续处理的加权和平衡表，约定照 R `WeightIt` 1.7.0 / `cobalt` 4.6.2（都是 GPL，只当黑盒，测试夹具 `tests/reference_parity/_fixtures/_generate_weightit_cobalt_R.R`）。二值处理就是两水平的多类别处理，三个方法共用一套核：多项 logit（Newton，得分到 1e-11）、恰好识别的 CBPS（各组 `(1, X)` 的加权和相等；ATT 时等于熵平衡）、逐组熵平衡（复用 `ebalance._solve_ebalance`）。几条从输出反推、核对过的约定：(1) 连续处理的 `glm` 权重是 `phi(z_A) / phi(r / sigma)`，两个尺度都是除以 `n` 的 ML 尺度，等于密度比乘常数 `sd(A)/sigma`，**不要**"修正"成密度比，否则与 WeightIt 差一个常数；(2) 连续熵平衡默认只保持处理与各平衡项的均值、协方差为零，`d_moments=k` 才保持 2..k 阶矩（WeightIt 文档说 d.moments 会自动抬到 moments，但输出里处理变量的二阶矩并未保持，以输出为准）；(3) WeightIt 的多项 logit 停在得分 1e-6，所以多项 `glm` 权重只对到 2e-7，CBPS ATT 它自己与熵平衡差 2.7e-9，我们对它的熵平衡 7e-13。WeightIt 的连续 CBPS 是一个不归零的 GMM 准则（`optim` 值 0.10，相关系数仍有 0.05），**没有实现**，用 `'ebal'`。cobalt 的平衡统计：标准差永远是未加权的，ATE 用全部组方差均值的平方根，ATT 用焦点组，二值协变量的标准差用除以 `n`（连续处理的相关系数里也是）；多类别的汇总是各比较的最大绝对值，方差比取 `max(vr, 1/vr)`。**cobalt 的成对标签不定方向**（本夹具上 'b vs. a' 是 b − a、'c vs. a' 是 a − c），我们的 `'g1 vs. g2'` 一律是 g1 − g2，测试按每对先定号再要求同号。数字型 0/1/2 处理不猜类型，要求 `treat_type=`。
- **调查权重（2026-10-19）**：`sp.ebalance(weights=)` 是 WeightIt 的 `s.weights`，**不是** `base_weights` 的别名：目标矩用抽样权重加权，被重加权一臂按 `s·w` 平衡（`w ∝ q exp(λ'c)`，`q` 是基础权重），两臂结果均值都带 `s`；M 估计的每条方程乘 `s`。两者同时给时与 WeightIt 对到 1e-9（从输出核对：WeightIt 的 `$weights` 不含 `s`，`weights_full` 也不含）。`sp.match(sampling_weights=)` 照 MatchIt 文档的配方（倾向得分用加权 logit、匹配不变、`lm(y ~ d, weights = 匹配权重×s)`、无放回按匹配集聚类 `vcovCL`，有放回 HC3），这个标准误不计倾向得分估计，是 MatchIt 文档推荐的那个，不是 Abadie-Imbens；`weights=` 仍是频数权重。k:1 无放回在对照不够时与 MatchIt 的匹配集不同（MatchIt 分轮补第 k 个对照），与抽样权重无关，夹具里没收这一格。`sp.ltmle(weights=)` 是 R ltmle 的 `observation.weights`：所有回归、扰动（`s / prod g`）、plug-in 均值 `Σ s Q / Σ s`、影响曲线 `s·(...) / mean(s)` 都带权，与 ltmle 1.3-0 对到 1e-10。
- **`dose_response/dr.py`（`sp.dose_response(method='dr')`，2026-10-19）**：Kennedy-Ma-McHugh-Small 2017 的双稳健剂量反应曲线。处理的条件密度用正态（均值回归 + 残差平方回归，方差有 `1e-3·mean(r²)` 的下限），干扰函数交叉拟合；`m(t)`、`mubar(t)` 在 n ≤ 1000 时逐点精确平均（O(n²) 次预测），更大时在 400 个分位点上算再线性插值，`model_info['marginal_averages']` 记着用的是哪个。带宽按局部线性的留一风险选（几何网格 0.05–1.5 个 sd(T)），带宽让某个观测剂量附近没有邻居时风险记为 inf。点态 SE 是伪结果上的稳健局部线性三明治，**不含平滑偏差**：已知真值测试要对"平滑后的真值" `Σ w_i(t) θ(T_i)` 比，直接对 θ(t) 比时凸曲线上 z 普遍偏正（实测 1–2），那是平滑偏差不是 bug。npcausal::ctseff（GPL，GitHub 安装到私有库，只当黑盒）与我们形状一致（内部相关 0.999），但它用核密度、分箱平滑和 SuperLearner，带宽与 SE（约大 65%）都不同，只算形状筛查。
- **`tmle/lmtp.py`（`sp.lmtp`，2026-10-19）**：纵向修正处理策略的序贯 TMLE，按方法独立实现，R lmtp 1.5.4（AGPL）只当黑盒。几条从输出核对的约定，**改了就对不上**：(1) 密度比用堆叠数据分类（自然行标 0、策略行标 1，两半的历史都是自然值，只把当期处理换成策略值），`r = p/(1-p)` 在自然行上取；(2) 截断是对**整个** n×K 比值矩阵取 0.999 分位数（R type 7），不是逐列（逐列在第一期差 1e-3）；(3) 结果缩放到 [0,1]，最后一步连续结果用线性回归、二值用 logistic，**中间各步的伪结果一律线性回归**（用 logistic 差 0.2%）；预测截到 [1e-5, 1-1e-5]；(4) 波动是 offset logit Q、权重累计比值的仅截距 logistic；预测策略下的 Q 时更早的处理保持自然值。`folds=1` 时与 R 对到 3e-7（R glm 的收敛容差）。二值处理的静态策略（"全部设为 1"）不是 MTP，用 `sp.ltmle`。`sp.ltmle(q_learner=, g_learner=)` 接任何 sklearn 风格学习器（含 `sp.SuperLearner`），学习器看不到常数列；logistic `g_learner` 与默认对到 1e-8。
- **2026-10-19/20 一轮的其余约定**：(1) `sp.policy_tree` 多行动树（`policy_learning/_multi_action.py`）：深度 ≤ 2 精确搜索就是二值版加一个行动轴，平局规则（叶内取第一个行动、分裂取第一个 (特征, 阈值)、分裂必须严格优于不分）与 policytree 1.2.4（MIT）逐行一致；`split_step > 1` 我们按不同取值稀疏、policytree 按样本稀疏，两者只在 1 时相同，夹具不收这一格。二值 0/1 处理且 `scores` 是一维时仍走原来的二值路径，数字不变。(2) `sp.match(method='cem', k2k=True)`（`matching/_cem_extras.py`）= 先 CEM 得到格子，再以格子为 `exact` 做无放回、Mahalanobis、数据顺序的最近邻（MatchIt 文档写明两者等价），与 MatchIt 4.7.2 的配对逐行一致；MatchIt 的 cem 粗化（Sturges 是箱数、边界值进高箱）与 R cem 包（我们的默认，Sturges 是切点数、右闭）不同，比较时给相同的整数 `n_bins`。`sp.l1_imbalance` 用与 `method='cem'` 相同的等宽粗化，R cem 的 `imbalance()` 默认粗化不同，数不能直接比。(3) `sp.aipw(ps_learner=, outcome_learner=)` 只换干扰函数，标准误仍是影响函数的，`se_method='sandwich'` 拒绝。(4) `sp.gate_test(clan=)` 的 CLAN 与 GenericML 一样是各组均值（`sd/sqrt(n_k)`）与"最强减最弱"的 Welch 差。**仍未做**：`ltmleMSM` 的多结局节点汇总（`final.Ynodes`）与 `variance.method='tmle'`、WeightIt 的连续 CBPS、连续处理的能量平衡（独立性权重）。
- **`matching/_energy.py`（`sp.weightit(method='energy')`，2026-10-20）**：目标函数从 WeightIt 1.7.0（GPL，只当黑盒）的输出反推、按 KKT 条件逐项核对（在参考解的自由权重上做最小二乘，残差到 1e-17 才定稿），**改了就对不上**：记 `v_t = w_t / n_t`，(1) ATE improved = `Σ_t [E(v_t, F_n) + λ/2 |v_t|²] + Σ_{t<s} E(v_t, v_s)`，三类项**不加权**；(2) ATE standard 每组乘 `(n_t/n)²`（惩罚项也乘）；(3) ATT 是 `Σ_{t≠focal} [E(v_t, F_focal) + λ/2 |v_t|²]`；scaled_euclidean 用 ddof=1 的标准差。QP 用原始-对偶积极集（每步解自由权重的 KKT 方程组），失败时退回原始积极集，不引入 osqp。15 个设定与 WeightIt 对到 1e-9（实际 1e-11）。**目标函数在某些方向上很平**：指示变量协变量 + 欧氏距离时 OSQP 停在离最优解 0.06 的地方、目标值只差 1e-11，所以那一格比目标值（我们更低），不比权重；WeightIt 对因子协变量的编码因此也无法从输出确认，我们按 StatsPAI 的 k-1 指示变量展开。
- **用户学习器（`core/_learners.py`，2026-10-20 起）**：`sp.aipw` / `sp.ipw` 的 `ps_learner=`、`sp.ltmle` 的 `g_learner=` / `q_learner=`、`sp.lmtp` 的 `ratio_learner=` / `outcome_learner=`、`sp.SuperLearner` 的库成员，一律经 `clone_learner`（sklearn clone，失败则 deepcopy）与 `positive_class_proba`（`(n,)` 原样，`(n, 2)` 按 `classes_` 取类 1 那列，其他形状拒绝）。`sp.SuperLearner.predict_proba` 返回 `(n,)` 是既有公开行为，没有改成 sklearn 的 `(n, 2)`（改了会让 `np.mean(sl.predict_proba(X))` 之类静默变成 0.5）。**新增接受学习器的入口用这两个函数，不要再写 `predict_proba(X)[:, 1]`**。2026-10-20 第二轮把其余接用户学习器的入口也接上了：`sp.dml`（irm / iivm 的 `ml_m` / `ml_r`，plr / pliv 的分类器经 `_predict_nuisance`）、`sp.dml_did`、`sp.dml_model_averaging`、`sp.dynamic_dml`（以前对分类器调 `predict` 拿硬标签做残差，⚠️ 数变了）、`sp.metalearner` / `sp.auto_cate` 的 `propensity_model`、`sp.causal_forest(model_t=)`（grf 与 legacy 两条路）、`sp.conformal_counterfactual(propensity_model=)`；`proba_or_predict` 是"有 `predict_proba` 取类 1、否则 `predict`"的那一种槽位用的；`(n, 1)`（单类折）按那一类给全 1 或全 0。包里剩下的 `[:, 1]`（约 30 处）都是模块自己构造、在已校验为 0/1 的目标上拟合的 sklearn 分类器，列 1 按构造就是类 1，没有改。`tests/test_learner_proba_routing.py` 对每个入口断言"单学习器 SuperLearner == 该学习器"（rtol 1e-9）。`sp.RlassoClassifier` 是线性概率模型（与 `hdm::rlasso` 对 0/1 标签的拟合逐位一致），线性预测出 [0,1] 的行被截到 clip=1e-3、做倾向得分时权重 1000，`sp.ipw` 上能把 ATE 从 1.2 拉成负数；它现在在截断生效时发 `AssumptionWarning`，倾向得分请用 `sp.RlassologitClassifier`（hdm 的 `rlassoLATE` 也用 rlassologit）。三个 rlasso 学习器的 `fit(sample_weight=非 None)` 抛 `TypeError`（以前静默忽略权重）。

- **`tmle/ltmle_msm.py`（`sp.ltmle_msm`，2026-10-20）**：R `ltmleMSM` 1.3-0（GPL-2，只当黑盒）9 个设定对到 1e-8。从输出核对的约定，**改了就对不上**：(1) 序贯回归**按方案分别拟合**（与 `sp.ltmle` 相同），但每个节点只有**一次**波动，所有方案堆叠、协变量是工作模型的设计 `x(d, V)`、权重 `h(d) w / g_cum`（把 `h x / g` 当协变量差 3e-3）；(2) `msm_weights='empirical'` 是**不加观测权重**的比例（加了差 2e-3），分子要求观测处理与方案一致**且**到最后未删失（不要求未删失差 4e-3）；动态方案按单位比 `A_i = d(i)`；"重复方案权重为 0"指**整个方案矩阵**与前面某个方案完全相同，**不是**逐单位重合（逐单位置 0 差 0.14）；(3) 连续结局按观测范围缩放到 [0,1]，工作模型描述的是缩放后的均值（与 R 相同）；(4) 影响曲线 `M^{-1} Σ_d h x (Σ_k H_k (Q*_{k+1} - Q*_k) + Q*_0 - m)`，`M = Σ_i Σ_d h w x x' m(1-m) / n`。
